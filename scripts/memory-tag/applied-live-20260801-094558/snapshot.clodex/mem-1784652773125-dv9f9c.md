deployment-plan: docs/deployment-plan.md written 2026-07-21 (design exploration, follows engine-as-substrate.md). Thesis: ONE node contract (image + env-var config + credential seeding + registration handshake), per-target recipes stay thin/declarative (compose, Fargate task-def, k8s manifest, SSH-as-one-recipe). Key recon facts it's built on: sandbox.js = orchestrate pattern already built for local Docker (resolveImage ghcr.io/avirtual/clodex:<version>, minted wire token, auth.env env_file, registerPeer); CLAUDE_CODE_OAUTH_TOKEN via `claude setup-token` = existing non-interactive Claude auth (NO ANTHROPIC_API_KEY path anywhere in repo); codex login = interactive-only, open problem; ALL reachability today is controller-initiates (ssh probe/tunnel/static forwards), nothing announce-shaped. Design: announce v1 = node dials home (CLODEX_CONTROLLER_URL/TOKEN → POST /api/peer/announce → auto-add to peers array) so any launcher works, zero cloud SDKs in Clodex; announce v2 (deferred) = reverse outbound channel for outbound-only nodes. Build order: contract+image hardening → announce v1 → recipes → codex auth → v2. NOT build-authorized; 4 open questions to Bogdan in the doc (ephemeral-vs-durable /data, shared-vs-per-node registration token, controller-must-be-reachable prerequisite, whose controller in the Fargate ask).
