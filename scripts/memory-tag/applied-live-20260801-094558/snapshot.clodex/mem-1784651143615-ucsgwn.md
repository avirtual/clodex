DAEMON DIRECTION (Bogdan, 2026-07-21) — settled thinking, revive-ready for Fable. Clodex's CORE (strip the million features): an ENGINE that wraps multiple CLIs, makes them interactive + REACTIVE, event-driven. The unit is a LIVING SESSION, not a command: `claude -p` is one-shot (spawn→answer→die); a Clodex-held session is a PTY kept ALIVE inside the daemon — spawned once, addressable for its whole life, instructable, correctable mid-flight, wakeable by events/agent-messages. That persistence IS the product. This makes headless Clodex a viable DAEMON on remote boxes (EC2/Fargate/k8s pods): headless-main.js keeps sessions alive across the box lifetime, SIGTERM-clean, exit-code-64 for supervisor restart (systemd Restart=always / k8s liveness / ECS restart) — built to be the long-lived supervised process. Sessions stay warm+reactive with NO GUI attached. "Control agents interactively" = read/write-a-session verbs over the wire (spawn, instruct, correct — all post-spawn). ARCHITECTURE ALREADY IS THIS (not aspirational): engine.js electron-free; 2 GUIs prove it's a server (Electron/ipcMain + web/remote.js wire — can't have 2 clients unless it's a server); GUIs = partial LENSES onto a subset of engine surface (surfaced visual capability + back-channel: agent-msg/event-reactions/schedules/relays/skills, many never windowed, first-class). Doc: docs/engine-as-substrate.md (uncommitted rewrite; old control-plane-plan.md shipped in v3.4.0 as 9d5168d).
