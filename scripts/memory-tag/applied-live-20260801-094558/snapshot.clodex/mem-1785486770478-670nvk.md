DISPATCHING AN EXISTING TICKET IS `assign`, NOT `add`. 2026-07-31: t120 sat as backlog; I dispatched it with `[agent:task add hand]` and minted t124 — same spec, two ids, one live seat. Had to cancel t120. The reflex "file the work" is correct only when the work is NOT already on the board; check the board first, then `[agent:task assign <id> <role>]`. Symptom that catches it: after dispatch the original ticket still reads `open | assignee: null` while a new id appears. This pairs with the other direction (mem: "the reflex to fix is add, not remember the board") — the rule is board-first, then add-or-assign.
