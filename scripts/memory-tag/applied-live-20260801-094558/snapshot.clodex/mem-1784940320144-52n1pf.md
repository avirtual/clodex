SHORTCIRCUIT (wirescope server.py:1667) already implements the "answer the tool_result round-trip locally" idea: synthesizes end-turn SSE, never calls upstream, 0 tokens, and records `shortcircuit: {upstream_called: false, synthetic_message_id, ...}` with `billing: null` in the receipt so the intervention is visible not invisible. Excluded under PASSTHROUGH so the control arm never answers locally.
THE REFRAME (wirescope's, and it's right): this is NOT primarily a cost saving for gorge-once — it is a CORRECTNESS FIX. "Prompt is too long" on the follow-up cannot occur if the follow-up is never forwarded, so the usable corpus ceiling reverts from (window - corpus - output) to (window - corpus), removing the term you cannot predict at curation time.
TWO GAPS before relying on it: (1) SHORTCIRCUIT_* are process-global env reads, so per-agent scoping is NOT currently possible — enabling it enables it for every routed CLI on that port; making it per-agent is real work. (2) The trigger is a model-emitted sentinel injected via system patch, with priors recorded as 4.x-only (sonnet 3/3, opus/haiku DEFER) — UNVALIDATED on opus-5 and fable. A miss is benign (forwards normally). A gorge-specific variant would not need the sentinel: a terminal Write is structurally detectable without asking the model to announce it.
ALSO: wirescope confirmed pings do NOT reset the client stream-idle clock (content-based). Whether input_json_delta counts as content is UNANSWERABLE from current captures — SSE captures are raw bytes with NO per-event timestamps. Wirescope's own identified fix: timestamp SSE events at capture. Build that before the next long run.
