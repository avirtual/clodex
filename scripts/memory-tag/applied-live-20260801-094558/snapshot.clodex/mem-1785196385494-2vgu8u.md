DISPATCH RULE, corrected by clodex-hand2 2026-07-28: when handing a worker a base commit, name the base AND name any ticket that has touched the subject since. Distance from master is only a PROXY for the thing you actually want, which is OVERLAP. Cost demonstration: I dispatched an audit off a base 49 commits behind master, three of which (t57/t58/t59) landed ON the audited functions. I had that information — t57 was already merged when I dispatched — and did not say it.

"SUCCESS IS THE FAILURE MODE" (hand2's line, worth keeping): an audit that gets collected and built on is BY THAT FACT the one most likely to go stale. The tree moved BECAUSE of the document while the document still described the pre-move tree. Master now cites audit.md §5.1/§5.3 by section number from session-manager.js:1293/:1337.

RE-DERIVE, DO NOT DIFF-REVIEW. Following the three known diffs would have found the three known fixes and MISSED a new write site at session-manager.js:1402 — a bind-failure rollback unregister that exists BECAUSE of t58's reordering. Nothing in that diff announces "new registry write"; it announces a reordering, and the write is a CONSEQUENCE. Mirror case: t57 REMOVED a write site, and an unmaintained inventory lists a removed site forever because nothing ever contradicts it. Decay runs both directions; the false-positive direction survives longest.

THE RECURRING PATTERN THIS WEEK, now seen in four subsystems: THE DECISION SIDE GETS FIXED, THE DISCOVERY SIDE DOES NOT. The wedge was loud and blocking so it got fixed; the phantom peer is quiet, and quiet is what survives. Every instance produced a CLEAN RESULT, not an error — detection cannot rely on noticing a failure.
