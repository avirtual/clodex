PLUGIN QUARANTINE / AUTO-DISABLE (design decided with Bogdan 2026-07-25; belongs in the Phase 2 W7 loader alongside the fail-safe activate() try/catch): the loader should auto-disable a plugin that repeatedly fails to activate. KEY DESIGN RULE: do NOT clear `uiSettings.plugins.enabled` — that field is the USER'S INTENT. Auto-disabling by flipping it destroys the record, so the user re-enables next launch with no idea it was ever off and the crash loop repeats. Instead keep a SEPARATE quarantine set (enabled stays true; quarantined shadows it), so the §2.5 settings row can show "disabled automatically: activate() threw on N consecutive launches — Retry" with user intent intact. THRESHOLD: quarantine on the SECOND consecutive failed activation, not the first — a single throw is often transient (missing git binary, network blip in an engine half); two in a row is a real crash loop. Persist a per-plugin failure counter, cleared on any successful activation. RENDERER NUANCE: the renderer half activates once per BrowserWindow, so a failure may be one window of three — quarantine on consistent failure across activations, not per-window. RATIONALE (Bogdan's thesis): plugin authors are technical and "if they break it it's on them to fix it" — but that only holds if breaking a plugin never costs them the app they'd fix it in. Fail-safe boot + quarantine keeps the blast radius inside the plugin.
