UNIFICATION ADDENDUM (2026-07-27) — Bogdan's lifetime model, refines the reach/use unit:

MENTAL MODEL: clodexctl creates EPHEMERAL connections (open one, do a bunch of things, close it). Peers are PERSISTENT connections (attempt to persist/reconnect). Ephemeral == persistent with retry budget 0 and lifetime scoped to the operation. One class, one config field.

TWO PARAMETERS FALL OUT, both places where current code disagrees with itself:

1. PORT STABILITY IS NOT A PEER/CTL DISTINCTION — it is a CONSUMER-CAPABILITY one. peer-tunnel.js re-picks localPort per respawn; web-tunnel.js PINS it. Both peer-side, both persistent. The real difference: peer-client.js re-reads urlFor(id) through onState so it can follow a moving port; a browser tab holds a dead string and cannot. Field = "can my consumer re-read the endpoint", NOT "am I a peer". Ephemeral connections get pinning for free (nothing outlives them to go stale).

2. FAILURE HAS TWO SINKS = second config field. Ephemeral dial failure exits with an error a human reads on a terminal. Persistent dial failure enters backoff and becomes a STATE the UI renders. Same failure, different destination — unparameterized, one caller ends up swallowing errors or spamming them.

RESULTING SHAPE: `Reach` produces a local endpoint speaking wire 7900. Three params on top: retry policy (0 = ephemeral), port stability (pinned when consumer cannot re-read), error sink (throw vs state). Layers above unchanged: clodexctl attaches (attach/exec/web), peers stream.
