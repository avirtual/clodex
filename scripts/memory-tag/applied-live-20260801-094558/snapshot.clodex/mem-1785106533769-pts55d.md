UNIFICATION — BOGDAN'S FRAMING (2026-07-27), supersedes my two-stores framing:

It is not two stores to reconcile. It is ONE CONCEPT implemented twice: "a list of other Clodexes, some peered, some not, each reached somehow." Clodex grew ssh + direct/sandbox; clodexctl grew tunnels (ssm/kubectl/gcloud/az). But ultimately every case is a remote Clodex reached over SOMETHING, consumed by a local Clodex.

TWO ORTHOGONAL AXES:
- REACH — ssh | url | ssm | kubectl | gcloud | az | loopback(sandbox). All answer one question: give me a LOCAL ENDPOINT that speaks Clodex's wire. A url already is one; a sandbox is loopback; the rest are tunnels. THIS IS THE ONE CLASS to build.
- USE — clodexctl's attach/exec/web (one-shot, terminal-shaped) vs Clodex-to-Clodex peer streams (persistent: hello/identity, session lists, PTY streams). Genuinely different and should STAY different; both merely take an endpoint as input.

WHY THE FRAMING IS SOUND (verified): both consumers already speak to THE SAME WIRE PORT 7900 — remote.js RemoteServer serves the peering protocol AND clodexctl's client. One protocol, two consumers; the entire split is in how each obtains a socket to it. (Note: the full browser frontend is a DIFFERENT server — web-host.js on 7810, started only by headless-main.js when CLODEX_WEB_PORT is set.)

THE ONE SURVIVING DIFFERENCE IS LIFETIME, and it is POLICY not protocol: clodexctl's tunnel is one-shot and dies with the command; a peer's is supervised (backoff, respawn, pinned local port because a browser tab holds a URL string and cannot re-read urlFor(id)). Same dial, different supervision — a parameter, not a second implementation.

REFRAMES THE 2026-07-27 BUGS as one failure: a peer record could not EXPRESS what clodexctl could reach (t32), then the web supervisor could not DIAL what the record had learned to hold (t36). Both are "reach" leaking into layers that should only consume an endpoint.

Bogdan's stated value: "it simplifies the whole thing conceptually." Design doc NOT yet written.
