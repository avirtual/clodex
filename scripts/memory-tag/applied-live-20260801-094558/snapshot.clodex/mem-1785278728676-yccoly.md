THREE PLACEMENT TIERS FOR A RULE, AND I DEFAULT TOO BROAD. (1) IPC block — mechanism true of Clodex everywhere; most expensive, sits in the frozen system segment, which is why ipc-prompt-cache.js exists. (2) Stock team prompts (resources/library/prompts/system/*.md) — how a ROLE works, in ANY project; these are SHIPPED, so every Clodex team everywhere loads them. (3) .claude/CLAUDE.md — THIS project's conventions, binding every agent working here including plain non-team seats that team prompts never reach. On 2026-07-29 I proposed the Clodex comment convention for tier 2 while correctly arguing it did not belong in tier 1 — same over-broad error, one tier down, made in the act of rejecting it. Test before placing: WHO ELSE RECEIVES THIS, and is the rule true for them? CLAUDE.md is not frozen-forever — the operator's constraint is that it busts cache ONE-TIME PER EDIT, so the discipline is BATCH edits and keep entries short enough to earn permanent residency, since every session carries the bytes forever.
