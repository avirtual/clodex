REFINEMENT to mem-1784926497358-km3nmc (memory-load awareness), Bogdan's key insight 2026-07-25: capability (1) LOAD-AWARENESS is more tractable than first framed, because Clodex EXECUTES every context state-transition rather than inferring it. The live-context model is just fold(events) over the intent stream Clodex already handles: session-start → inject pinned-in-full + index = initial live set; [agent:context clear] → drop all except re-injected pinned; [agent:memory recall <id>] → append that unit to the live set w/ timestamp; [agent:context compact] AND the CLI's own auto-compact → the one lossy edge. Even compaction isn't a blind spot: Clodex knows the compaction boundary + timestamp, it just can't see which facts the summarizer preserved → model marks units "possibly-evicted, last-confirmed-loaded at T" (confidence downgrade, not guess). No new observation channel needed — pure bookkeeping on transitions Clodex causes. This deterministic live-set is enough to drive self-correcting pruning: "unit in index across N sessions, recalled 0 times, superseded → archival candidate." Retrieval half (2) complements: re-surfaces a unit a compaction may have dropped.
