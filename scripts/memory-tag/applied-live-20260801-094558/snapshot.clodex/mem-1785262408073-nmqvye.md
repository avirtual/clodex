REMINDERS CARRY INSTRUCTIONS AND POINTERS, NEVER STATE. (Learned 2026-07-28.) I scheduled a 2h dispatch-watchdog reminder for the t75-t78 cluster and pasted the current "waiting on you" list into it. It fired after everything had changed: cluster closed, the A/B command's port occupied and its LOG_DIR stale, the "4 unpushed commits" moved to a branch, the "nine merged fixes aren't live" already superseded by an app restart. Four of five items false on arrival, one never verified.

The trigger half was still perfectly good — "read tickets.json for lastActivityAt, check the seat with [agent:who], look for the journal, a dead seat is respawned from the artifact never resumed, do NOT assume silence means progress." Timeless because it says WHERE TO LOOK rather than what is there.

Rule: a scheduled message is a claim about the future and decays like any comment, but arrives with the authority of the system briefing you rather than as a claim to verify — so it is worse than a stale comment, not equal. Write reminders as: trigger condition + where the state lives (artifact path, tickets.json). Never paste a status list into one.
