Cross-repo claims must name the tree and use file + matchable TEXT, never "this repo" or a bare file:line.

Failure, 2026-07-31: I told wirescope "this repo already settled it" about the point-by-symbol rule. True of wb-wrap-ui (.claude/CLAUDE.md, "another file's behaviour (it drifts silently — point by symbol, never by line number)"). wirescope grepped proxy-lab, came back genuinely empty, and nearly published a confident correction. The check was well executed and aimed one repo to the left.

Why it is structural, not carelessness: "this repo" is fully determined at the writing end and undetermined at the reading end, and NEITHER side can feel the gap. You cannot notice an ambiguity you do not have; the reader resolves it silently to the only tree they are in. A truthy answer about the wrong object — same class as endpoints.hint vs hints.

What rescued it: I resent it as file + quoted text, which wirescope confirmed in one grep across a repo it had never opened. The line number did none of the work. A bare CLAUDE.md:179 would have made it guess which of several CLAUDE.mds on this machine, and a plausible line 179 in the wrong one would have "confirmed" something.

Rule: name the tree, quote matchable text, treat the line number as decoration. Same reasoning as the comment rule it was about — an address that self-checks beats one that merely looks checked. Carve-out: file:line is correct in task specs (drift window is one task, hand reads the live tree) and in changelog entries (anchored to a commit, true at that commit forever).
