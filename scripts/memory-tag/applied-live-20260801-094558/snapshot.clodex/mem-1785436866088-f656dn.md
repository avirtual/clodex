PLUGIN API DIRECTION (operator, July 2026). Bogdan's position: the plugin API today is "mostly UI oriented", and "the future value is in augmenting the agents". Treat agent-augmentation surfaces as the growth axis, not more UI slots.

Measured gap behind this: Clodex's distinctive competence is metering what reaches an agent and what it costs — park gate, hold gate, free-ride acks (session-manager.js:2526, drained at next UserPromptSubmit, zero tokens), >500-byte spill-to-file (:3723), boot digest baked pre-spawn into the SessionStart hook (cli-hooks.js:20), late-boot digest repair (:2512). Plugins reach NONE of it: `handle.inject()` maps straight to `manager._injectText` (plugin-host-engine.js:118), bypassing the whole envelope. Seven UI slots for drawing, one crude primitive for reaching an agent.

Candidate additions, priority order, all additive so hostApi stays "1": (1) `handle.ack(text)` — free-ride channel, mechanism exists and is tested; (2) `handle.deliver(text,{kind})` — the envelope incl. spill, with `inject` kept as the raw typing primitive; (3) pre-spawn context contribution — HELD, needs a token budget + visible attribution first, since a plugin could otherwise put 100k tokens into every conversation a seat ever has with no signal to the operator.

CAVEAT that must ride any of these into the doc: acks and the digest both gate on `agentType === 'claude'` and fall back to inject for codex. Exposed under a generic name they'd read as "free" and be "free on Claude, a full turn on codex" — a false-green unless documented.

DECIDED NOT to extract memory or tickets into plugins. Generalisable test that produced it: does the feature participate in session BOOT, or cross the PEER wire? Either one means it cannot be a plugin at hostApi "1" — both paths are deliberately closed (§13). Memory fails on boot (the digest is what makes memory work at all); tickets fail on both (157 refs in session-manager.js, plus api-contract.js/peer-import.js, and plugin channels are off the peer query whitelist by construction).
