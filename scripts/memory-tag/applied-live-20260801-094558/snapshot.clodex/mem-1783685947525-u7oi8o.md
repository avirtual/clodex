Wire intent-path swallow points (found 2026-07-10 investigating the "compact intent didn't parse" incident): (1) IntentDeduper.claim() at session-manager wire dispatch happens BEFORE downstream guards — a context-compact that the in-flight guard then DROPS still poisons the 60s dedupe key, so a retry emission with the same body within 60s is swallowed with ZERO logging. (2) Slash-command injections (/compact) written into a BUSY CLI are refused/dropped by Claude Code (slash commands can't be queued mid-turn) — a compact intent sharing a turn with other intents whose handlers inject into the same pane (e.g. resend confirmations) loses the race: the confirmations wake the CLI into new turns and the /compact lands mid-turn and evaporates, leaving the compact guard armed until the 5-min valve. Fix direction (spec'd, pending): gate slash injections on prompt-parked state (session.lastMainStop.isTurn), log deduper drops, key dedupe on reqId so distinct emissions never collide (deduper's real purpose is same-emission wire/jsonl double-fire only).
