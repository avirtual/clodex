Task artifact directory names and ticket ids are SEPARATE sequences and drift — do not assume `tasks/tNNN-*` matches ticket tNNN. Cause is structural: the lead names the directory while writing the spec, before `[agent:task add]` mints the id, so they can only agree by luck. One lead-done task with no ticket (t111-roster-survives-context-reset) put everything after it permanently off by one.

Rules: read the ticket id off `[agent:task list]` output, never off the directory name. When dispatching, tell the hand which id to close in the ticket body. Better still, name new directories for the SUBJECT with no number at all (`tasks/digest-order-and-fallback/`) — the number adds nothing a grep can't recover and is actively misleading when wrong.
