REVIEW PRINCIPLE, earned in Phase 3 and generalizable beyond plugins: a contract reviewed only by people who can read the implementation gets reviewed for CONSISTENCY, never for SUFFICIENCY. Every such reviewer silently resolves an ambiguity by checking the code — the exact move the contract's real audience cannot make. Four internal passes (a shape pass, a contract test with literal tables, my own deliberate outsider read, a cold boundary review) all missed that docs published `handler(intent, ctx)` while the code calls `handler(handle, intent)`. It was found in minutes by an agent given ONLY the doc, in a scratch directory with no source present.
SO: for any published interface, the acceptance test is a build performed by someone who CANNOT see the implementation. Not a review — a build, because only a build fails when a doc is silent. Enforce the isolation structurally (empty directory + the doc), never by instruction; an agent told "pretend you can't see core" will still peek.
COROLLARY: their "what I had to assume / what was missing / what misled me" log is the deliverable, equal in value to the code.
