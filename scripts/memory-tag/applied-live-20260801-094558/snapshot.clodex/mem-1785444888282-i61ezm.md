Curation of agent memories must MARK and POINT, never rewrite or delete. Additive front matter only — superseded_by, verified_at, subject, tags — so every pass is a reversible diff and a bad pass is recoverable.

The case that settles it (wirescope, 2026-07-30): a pinned unit recording an incident ended with a seven-item carried TODO list. Two items had become false and were re-pasted across sessions rather than re-verified. That unit was simultaneously the most load-bearing thing in the store AND partly stale. An LLM rewriting it would have emitted a confident, clean, current-looking list and destroyed the evidence that items had gone stale — the staleness was detectable only because the original text survived intact.

Two consequences: (1) never score or prune memory units by age alone — load-bearing and stale are independent axes. (2) The same disease applies to any carried list: a TODO carried forward needs re-verifying, not re-pasting. This repo already settled the identical question for code comments (CLAUDE.md: prefer deleting a stale comment to rewriting it, because a rewrite resets apparent freshness without anyone re-verifying the claim).
