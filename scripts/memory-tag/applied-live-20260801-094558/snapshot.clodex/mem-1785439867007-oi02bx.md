Grep/perl-based mutation harnesses are an unreliable instrument in this repo — two independent false tallies in one session (my `perl -0pi -e` on t111 reported "16 pass" from a regex that never matched; clodex-hand's harness on t112 reported all five mutants SURVIVED from a grep that never matched). Both failures are silent and both are shaped like a real result.

The rule: a mutation harness must (a) assert the mutation actually applied — `assert old in s` on the exact substring, not a regex — and (b) assert the baseline is green immediately before and after each mutant. Write it in Node/python3 parsing runner output, never as a shell grep pipeline.

The tell that catches it without any of that: an implausible tally shape. All-N-survive and all-N-pass are both far more likely to be a broken harness than a real finding. Check the shape before believing the number — a false tally pointing at "your tests are worthless" is cheap to recover from, the same bug pointing the other way ships a false green.
