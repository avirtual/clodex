PLUGIN LOADER GAP (found 2026-07-25, must land in Phase 2 W7 with the loader): docs/plugin-plan.md §3.1 specifies a named refusal for a manifest `hostApi` MISMATCH, but does NOT specify what happens when a plugin's `activate()` THROWS. Timing makes this critical: the engine half activates at the end of createEngine's electron-free bootstrap, BEFORE the handle returns and BEFORE any window exists. An uncaught throw there kills app startup with no window ever created — so no in-app session can be opened to repair the offending plugin, which breaks the self-repair loop (Bogdan's thesis: "if they break it, they can start a CLI in the same cwd and fix it"). REQUIRED: try/catch per plugin around both engine activate() and renderer activate(); a throwing plugin is marked failed and SKIPPED, the app boots regardless, and the failure surfaces in the §2.5 settings section (and ideally a toast). Same treatment for a malformed manifest. Rationale: a broken plugin must never cost the user the app; CLODEX_PLUGINS=0 and a bare terminal `claude` are the outer fallbacks but both mean leaving the app. ADD THIS TO THE t4 (W7-W9) TICKET SPEC.
