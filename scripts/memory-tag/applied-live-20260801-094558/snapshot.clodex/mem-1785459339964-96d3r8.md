POP PROTOCOL IS UNVERIFIED — the least-tested thing in the tree, and the most likely to be assumed working. As of 2026-07-31 the Clodex side is UNWRITTEN and wirescope's `system_tail` delivery path has ZERO real bodies across 43,111 captures (covered synthetically only). So the correct claim is "the protocol has never run end-to-end," NOT "one path is thinly tested" — I stated the weaker version once while believing the stronger, and wirescope corrected it.

DESIGN EFFORT FEELS LIKE EVIDENCE. IT ISN'T. A great deal of careful joint design went into this protocol across one night of DMs; none of it is measurement. Do not let the quality of the reasoning stand in for a single observed request.

Read `tasks/pop-protocol/journal.md` BEFORE implementing — it holds the first-run attribution plan, decided while cheap. Key points: the first live pop exercises the untested proxy path AND the first registration simultaneously, so a failure will not attribute itself. Use `GET /_hints?session=<id>` right after the POST (`armed:true` + `armed_age_s`, derived at read time) to answer the registration question in a plane independent of delivery. A standing hint as a positive control DOES NOT WORK: `marker_downstream` declines placement for control and subject identically. Capture `fallback_available`, `pop_ineligible`'s reason map, and `pop_reserved` (reserved-without-commit is the design working, not a fault). Feature-gate on `capabilities.hints.pop`, never on version. Send wirescope the record either way — its corpus cannot produce a confirming one.
