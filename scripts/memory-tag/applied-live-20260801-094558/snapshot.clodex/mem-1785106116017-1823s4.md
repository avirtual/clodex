CLODEX/CLODEXCTL UNIFICATION — analysis + recommendation (Bogdan raised it 2026-07-27, design doc NOT yet written; his call whether to build).

THE OBSERVATION: clodexctl imports peers from Clodex AND Clodex imports contexts from clodexctl. Verified: NO code cycle — `cli/` is a strict leaf, 0 upward imports, 3 downward (peer-tunnel.js:35, peer-import.js:33, stores.js:46). But a real DATA cycle: two stores holding the same record with a read-only importer each way (cli/src/import.js reads ui-settings.json peers; peer-import.js reads contexts.json).

THREE INSTANCES of the same boundary being wrong, all found by a user hitting them, none by a test:
1. Two importers (~400 lines) whose only job is shuffling between shapes that already mostly agree.
2. `ctx import` REFUSES a cloud peer clodexctl itself deployed — 0 matches for ssm|kubectl|gcloud in cli/src/import.js, so a k8s peer round-trips back as "no usable url/ssh transport (refused)".
3. Two dial supervisors that drifted — t36: web-tunnel.js stayed ssh-only on a ruling t32 had falsified, shipping a kubectl peer with working sessions and a refused web view.

SCHEMA IS ALREADY ~90% UNIFIED and deliberately so: same kind names, same field names, and stores.js:46 imports the CLI's validateEntry as final arbiter. What is duplicated is the two TRANSLATION layers, not the schema. Cost today: a new transport = FOUR edits (argv builder, CLI validator, PEER_CLOUD_KINDS, both importers).

THREE REAL BLOCKERS to a naive single store:
- DATA vs CODE. The CLI store legitimately holds `tunnel` (a raw argv). The GUI store is written FROM THE RENDERER, so one store = a GUI-editable command line the app executes. Non-negotiable.
- Write cadence. ui-settings.json is rewritten constantly (bounds, theme, session state); contexts.json is 0600, hand-editable, written only on explicit verbs.
- Neither store is only transports (contexts has `current`; peers have label/disabled/id; ui.boxes has per-box wirePort).

MY RECOMMENDATION: one shared transport-descriptor leaf (kinds + required/optional fields + validation) imported by both — a new transport becomes ONE edit. The GUI LISTS contexts.json entries live alongside peers instead of an Import button that copies (no stored pointer = no stale pointer; the peer-import.js:6-15 argument was against back-REFERENCES, not against a live view). `tunnel` entries show as present-but-not-dialable-from-the-GUI, never copied into a peer record. Sandboxes stop being snapshotted into contexts — their address is DERIVED, which is why a rebuilt sandbox leaves a stale context.

DO NOT fix instance 2 by teaching `ctx import` about cloud kinds — that is a fourth edit-site in the pattern being deleted.
