WILD PATTERN (Bogdan flagged 2026-07-25, "useful in the wild"): the "gorge-once brain" vs "lean orchestrator" split — two OPPOSITE context strategies for two different job shapes, and the skill is routing each job to the right one. (1) SYNTHESIS job (one big cross-cutting question, answer derivable in ONE pass, inputs discardable): feed EVERYTHING upfront to a disposable 1M agent, emit one artifact, die. Pays the corpus exactly ONCE (no turn two). (2) LONG INTERACTIVE job (orchestrator/lead): stay LEAN, hold conclusions not inputs, delegate big reads to dying throwaways — because carrying the corpus means RE-BILLING it every turn. KEY INSIGHT: incremental discovery has a hidden QUADRATIC cost — an agent reading file A(t1) B(t2) C(t3) re-bills A three times; the brain pattern is a different cost CURVE, not a constant-factor win. COROLLARY (self-critique that landed): even a lean orchestrator accumulates sediment across a LONG single session — the fix is COMPACT/CLEAR aggressively at PHASE BOUNDARIES (distinct jobs carried forward as one context = the waste). And: after handing off to a brain, the orchestrator should SHED context to review the output COLD (fresh reviewer beats accumulated thread). Pipeline shape: curate (cheap fan-out throwaways -> manifest) -> assemble (cat, free) -> synthesize (the 1M gorge) -> review cold (lean). Transport for the gorge: --append-system-prompt-file (ungated, see mem about that). This is arguably a productizable clodex primitive ([agent:exec brain] / one-shot synthesis intent) if it recurs.
