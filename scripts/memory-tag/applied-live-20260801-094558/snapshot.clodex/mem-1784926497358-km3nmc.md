PARKED PRODUCT IDEA (Bogdan, 2026-07-24) — "memory-load awareness": Clodex should be (kind of) aware of what's loaded in an agent's memory/context. Two distinct capabilities: (1) LOAD-AWARENESS — Clodex tracks which memory units are currently live in an agent's context (what it injected at session start, what survived compaction, what was recall'd mid-session). Foundation already half-exists: Clodex MEDIATES all memory I/O (it injects pinned+index at start, handles every [agent:memory recall]), so it already knows what it PUT in — the gap is the live post-compaction model. (2) BACKGROUND RETRIEVAL — a background process that semantically searches the memory corpus and proactively surfaces relevant units against current work, so the agent needn't know an id or craft a query (embeddings/index over units — bigger lift). KEY CONNECTION: (1) makes memory bloat self-correcting — units never recalled or superseded become archival candidates automatically, addressing the "too many memories / index load cost" problem that prompted this.
