Clodex plugin authoring toolchain, built 2026-07-30 (uncommitted at time of writing). `plugins/` is now self-contained: plugin-api.md and plugin-sources.md moved from docs/ into plugins/ FLAT (not plugins/docs/) because the loader only scans subdirectories, so .md at the plugins/ root is inert. Refs updated across 16 files; tasks/** journals deliberately left stale as historical record. New `plugins/tools/`: build-context.js (generates the agent context pack fresh, 41k tokens full / 31k --lean, gitignored, NEVER committed — a committed pack is a second copy that drifts), scaffold.js (generates id+dirname from one arg so they cannot disagree; validates via the host's own isValidPluginId, which refuses reserved names like `enabled` that a bare regex accepts), verify.js (drives the REAL loader+engine), control.js (verify.js's own 8-mutant suite). Loop: build-context -> scaffold -> verify. A fresh scaffold passes verify 13/13 immediately. KEY DESIGN: the pack's facts table (hostApi, PLUGIN_ID_RE, PLUGIN_VERB_RE, reserved ids, all 16 core verbs + end/escape/unknown) is EXTRACTED from plugin-api.js and intent-registry.js at run time, never restated — plugins/plugin-api.md:143 and :1068 hand-copy those regexes with nothing pinning them. Generating on demand dissolves staleness rather than checking for it. test/plugin-boundary.test.js pluginIds() narrowed to dirs containing manifest.json (same test the loader applies) so plugins/tools/ is not linted as a plugin.
