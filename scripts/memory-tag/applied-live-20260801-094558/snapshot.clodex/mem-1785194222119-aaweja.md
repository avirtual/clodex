PLUGIN ONE-SHOT VS AGENTIC EXPERIMENT (2026-07-28). Bogdan's design, repeating the plugin-plan experiment on a GitHub plugin.

ARM A (agentic, DONE): general-purpose subagent, isolated worktree, full tool access, told to build from docs and report gaps. COST $10.50, 200 requests, ~1915s, 167,778 subagent tokens. Output: plugins/github/ in worktree agent-a03f6334419f02eda — 4 files ~1180 LoC, one verb [agent:gh] with 4 sub-commands (status/pr/ci/review). Scope fence held (one untracked dir, zero modified files). No credentials — shells out to gh. Tested live against real repos incl. nodejs/node and electron/electron.

ARM B (one-shot, RUNNING): same brief, tools restricted to Read+Write ONLY so exploration is structurally impossible. Input = docs/plugin-api.md + docs/plugin-sources.md concatenated (113KB, ~28k tokens) + git-branches plugin as reference (18.6KB). Output to scratchpad/oneshot/github/. Expected cost ~$2.

MY PREDICTIONS, recorded BEFORE arm B ran so they are falsifiable:
1. The `pr` verb will be WRONG OR ABSENT — bodyMode:'greedy' is documented but intent.body is NOT (verified: zero occurrences in docs/plugin-api.md; assigned at session-manager.js:2918-2919). A docs-only agent cannot know where the body arrives.
2. It will inject multi-line prose with NO caveat — the bracketed-paste dependency (inject-queue.js:98, mode 2004) is undocumented.
3. It will NOT cap reply size — no stated limit exists anywhere.
4. Verbs will be THIN (gh-pr-create, gh-issue-list) rather than workflow-collapsing — collapsing requires knowing what agents fumble, which is discovered not documented.
5. It will LOOK PLAUSIBLE — no syntax errors, correct manifest. Failures will be the invisible kind.

THE REAL QUESTION: not cost-vs-quality, but whether one-shot failures land PRECISELY on the known doc gaps. If predictions 1-3 hold, the gaps are proven BLOCKERS (arm A only overcame them by reading core source), which converts the doc-fix ticket from hygiene to load-bearing.

ARM A'S DOC FINDINGS (independently verified by me): intent.body undocumented (0 hits in plugin-api.md); inject() multi-line/bracketed-paste caveat undocumented; no stated inject size cap (arm A guessed 3000 chars); two doc errors still shipped despite being filed in plugins/git-branches/NOTES.md, incl. a fix recorded as "dispatched" that never landed.
