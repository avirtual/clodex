MY SPEC ENUMERATIONS HAVE BEEN ONE SHORT FOUR TASKS RUNNING (t112 _teamLiveSeats, t113 ×2, t114/t115 six sites). The pattern is NOT "I miss files" — it is that I grep the tree in front of me and treat that as THE tree. `cli/`, `scripts/`, `peering/`, `plugins/`, and `web-dist/` bundled copies are all first-class in this repo and none appear in a root-level `--include=*.js` grep. Standing fix: name the CLASS in the spec, hand the site list over explicitly labelled A STARTING SET, and require the assignee to close it and report what I missed. Corollary learned at t114: when I call one implementation "the correct model, copy it," I must read WHICH PART makes it correct — I cited `plugins/memory-viewer/engine.js` agentDir() as the reference guard without reading its regex, which was as broken as everything else; only its dirname check was load-bearing.
