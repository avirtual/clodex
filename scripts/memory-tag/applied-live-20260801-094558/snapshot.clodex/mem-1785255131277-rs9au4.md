CLODEX INTENT BATCHING LIMIT (measured 2026-07-28, cost me a false "four tickets assigned" report): **only ONE `[agent:task assign ...]` intent fires per turn.** Emitting four in one reply assigned only the FIRST; the other three silently did nothing — ticket state stayed `assignee=None` with an untouched `lastActivityAt`, and the board still showed them `open`, which reads identically to "never dispatched". No error, no bounce. Verified by re-emitting one per turn and re-reading tickets.json between each.

ALWAYS verify a dispatch landed by reading `~/.clodex/teams/<team>/tickets.json` (list of records; `id` is the STRING "t75", not 75; fields: id/state/assignee/taskDir/spec/lastActivityAt/title). Do not trust the fact that you emitted the intent. This is the same false-green class as t92 (a ticket reported delivered that had parked) — the difference is that t92's failure was in delivery and this one is in the intent never firing at all.

Unverified whether this one-per-turn limit applies to other intent verbs (`task done`, `dm`, `spawn`). `task done` + `task assign` in the SAME reply: the `done` fired and the first `assign` fired, so the limit appears to be per-VERB rather than per-reply. Treat multi-intent replies as suspect until measured.
