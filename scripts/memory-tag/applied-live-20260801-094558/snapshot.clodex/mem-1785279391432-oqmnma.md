WATCHDOG REMINDERS ACCUMULATE ONE PER DISPATCH AND I NEVER CANCEL THEM. 2026-07-29: four live watchdogs on ONE branch, all stale, plus five cleared earlier the same evening — nine total, one ever useful. I twice told the operator it was a single miss with no duplicates; both statements were wrong, and [agent:remind list] is what corrected me. MECHANISM: arming is part of dispatch, but cancelling is not part of anything — the report arrives, I act on it, and acting FEELS like closing the loop. Nothing ever subtracts, so the set grows monotonically while accuracy decays to zero, and stale reminders INTERRUPT with the authority of something I decided mattered. PRACTICE: cancelling is part of receiving, not part of cleanup — the turn that handles a report cancels its watchdog, by id, in that same turn. And [agent:remind cancel] with no id bounces; capture the id when arming or run [agent:remind list] first.
