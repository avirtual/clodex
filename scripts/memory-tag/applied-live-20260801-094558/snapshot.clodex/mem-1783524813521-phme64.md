Multi-host orchestration — parked design note (brainstorm 2026-07-10, prompted by Simon Villiard; NOT approved work; supersedes mem-1783520236774-s7c9ng which carried a false premise). CORRECTED PREMISE (per wirescope): warmth is NOT per-host. The prompt cache is at Anthropic, ORG-scoped — both laptops on one account share one cache (custom base URL = 3P/org path). Warmth is a property of the upstream byte-lineage, host-independent. What IS per-host is the LEDGER'S EPISTEMICS (receipts honest only from the observing proxy) and ACTUATION (ping/hold need the in-memory last-request body + donated auth, which live only on the observing host). Conclusion unchanged and CORRECT: host-local proxy + host-local ledger, federate classified metadata only (cost/activity/busts/attention), NEVER wire traffic, NEVER sync warmth.sqlite (a copied row asserts pingability the receiver can't act on). Consequences: (1) fast-migration inside TTL costs one avoidable bust — B's ledger says cold, strips bytes, busts an upstream-warm prefix; rare, accept it. (2) strip-level override does NOT follow a migrated session — clodex must re-assert [wirescope:strip-thinking] per-session on attach (phase-b checklist item). (3) migrated session = "unknown, assumed cold" not "cold, correctly"; no invariant corruption (raw transcripts, cosmetic bust-counter reset). (4) merge MONEY (cost additive, fleet-spend real) never WARMTH (per-lineage boolean, only actionable on the holding host) — render warmth per (host,session). (5) org-cache extends cross-host: host A's fleet keeps the shared static segment warm for host B's fresh spawns IFF transform flags + wirescope version + CLAUDE.md are byte-lockstep — so version-lockstep between laptops is an ECONOMIC argument, not just hygiene; per-host ledgers under-report warmth on the shared segment (cold spawns may bill warm). Transport: SSH tunnels to localhost-only endpoints, zero new auth. Cheapest phase-(a) transport = wirescope's existing push feed (turn.completed carries cost+context+warmth receipts) over an ssh -R reverse tunnel (terminates on loopback, no exfil-guard loosening, no daemon needed). Identity: /_identity handles N-proxy via per-host capability gating; derive host identity from /_identity content NEVER from localhost:port (tunnels make everything localhost); wirescope offered a stable instance/boot-id addition (small, useful, not commissioned — Bogdan's call). Version-skew degrades features unevenly — gate on capabilities per host. Naming: name@host, resolve bare names at DELIVERY time (ambiguity is temporal), bounce with candidate list on collision. Prerequisite: extract SessionManager+watcher+registry+intent routing into a headless per-host daemon (clodex2 thesis; multi-host is its forcing function). Known breakages: DM spill-file pointers (~/.clodex/messages host-local — inline/ship body), [agent:file view] carries content not path, workspaces = (host,session) pairs reusing failed:true for unreachable. Failure modes to design against: laptops are ASLEEP most of the time (unreachable = calm first-class state, not error toast); half-open tunnels render stale-as-live (heartbeat + ServerAliveInterval, never render a remote chip without its age); DM-replay money-bomb (flapping tunnel re-delivers queued DMs, each wake re-bills a cold agent's full context — dedup by stable message id, rate-limit idle-cold deliveries); treat remote-relayed intents as DATA by default (spawn/file-view/memory-write from a remote host needs explicit allowlist). Phasing: (a) cross-host activity/DM federation over reverse-tunnel push feed, (b) daemon extraction, (c) [agent:spawn host:B]. Review pass with Bogdan pending (2026-07-10 update: the contrarian agent is retired; no contrarian pass will happen).
