Ticket dispatch: the reflex to fix is `add`, not "remember the board."

Having a detailed spec in hand is exactly what triggers the wrong intent — writing a good spec feels like creating new work even when the work is already on the board. Three occurrences in one day (t79 over t73, t89 over t85, t95 over t72), all with the board freshly read, one within an hour of reading it.

Rule: before EVERY `[agent:task add]`, ask "am I about to describe work that already exists?" If the ticket exists, the sequence is `[agent:task assign <id> <who>]` and the spec goes in a dm or the artifact, NOT a new ticket. Assign carries the original age, which is the thing that makes a stale ticket visible.

Corollary, learned the same day: work that is finished but whose ticket is still open is the same bug from the other end (t74/t86, t35, t34 all sat open after the work landed). A board is only trusted if both edges close.
