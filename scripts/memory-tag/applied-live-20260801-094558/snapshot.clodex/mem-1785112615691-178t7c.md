RELEASE HAZARD, TWICE NOW — WEB-DIST WORKTREE PATHS. esbuild embeds RESOLVED module paths, so a web-dist/index.html built inside a git worktree carries `../wb-wrap-ui/node_modules/@xterm/...` references. It commits clean and the suite stays green; only a grep reveals it. Bit us at v4.3.x (dirty-tree preflight block) and again at v4.4.0 (t45's bundle, built in the hand's worktree).

CHECK BEFORE EVERY RELEASE: `grep -o "\.\./[a-z-]*wb-wrap[^\"']\{0,30\}" web-dist/index.html | sort -u` — any output means rebuild. Fix is `npm run build:web` FROM THE REPO ROOT, then commit the regenerated bundle.

WORTH AUTOMATING: this is a packaging-class defect the same shape as the build.files allowlist ones — silent, invisible to tests, only findable by looking. A test asserting web-dist contains no path escaping the repo root would close it permanently. NOT YET DISPATCHED.
