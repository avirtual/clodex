BUILT-IN EXEC TOOLS tier (Bogdan, 07-18 — product framing that WRAPS the Monitor→intent build; treat as one thread). Insight: Clodex's power features are mechanisms only we know how to use (exec registry, gating, intents) — "we add the features, but it's only us who truly know how to use them." Direction: while correcting things (roster review etc.), ship the expertise as enable-able tools, not tribal knowledge. Users could use the regular Monitor tool OR "the clodex monitor" exec intent for roughly the same result — coexistence, adoption over fiat, nobody's tool is taken away. Design decisions to settle in spec: built-ins ship DISABLED-BUT-VISIBLE (library pane, one-paragraph what/when per entry; enabling wires exec grant + IPC-prompt help line in one click — visibility is the discovery fix); namespace rule for built-in vs user entries (shadow or refuse); built-ins version with releases (release-notes material, generated-bytes discipline); user vs built-in tiers visually distinct for grant audits. Monitor = the pilot built-in; later candidates: test-runner (now a subagent), task-status checker, dist-build. Presentation beat: "Clodex ships the expertise, not just the wrapper" — monitor demo = agent arms a watcher in one line, zero context cost. Fold into the Monitor spec as its framing, NOT a separate concept doc.
