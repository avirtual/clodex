THE COMMENTS ARE AN UNVERSIONED SECOND SPECIFICATION. Measured 2026-07-29: repo JS excl. tests is 3,231,452 bytes, 45.4% comment; twelve files over half; session-manager.js is 210,398 comment bytes of 373,021; 823 comment lines name another module. 3,000 tests gate the code half. NOTHING gates the prose half. The failure mode is not verbosity — it is that at read time a comment is indistinguishable from truth, arrives with the same authority as code, is easier to read, and is written in my own confident voice, so I reason from it IN PREFERENCE TO the code. All three comment-defects found by cold review that night were cross-file assertions, and I endorsed two as correct. It compounds: each block is written by an agent that just did the work and was sure, then the next agent believes it and writes its own on top. RULE (t105): a comment may POINT at another module ("see X", "mirrored in Y") but may never assert what that module does; a cross-file property stated as fact needs a test that fails when it stops being true, cited by name. Local constraint records (the flat-copy rule, ipc-prompt-cache's level-vs-edge header) are the genre that EARNS its keep — a density-based cull would delete those first, which is why the fix is by shape, not by volume.
