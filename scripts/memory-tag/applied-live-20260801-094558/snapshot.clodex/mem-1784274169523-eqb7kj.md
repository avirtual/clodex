MONITOR→INTENT reclaim (07-18, SIZED+DESIGNED, post-relaunch clodex WRAPPER build — this is the promoted form of the parked [agent:monitor] idea). WHY it beats a deny: Monitor is load-bearing in core (66 calls/29 sess, can't deny) but its 1.9k-tok tool schema (7659ch, ~1.5k is the description) rides tools[] every loaded turn whether it fires or not. Converting it to an exec/intent captures the schema cost WITHOUT losing the capability — the only lever that touches core, which is otherwise all load-bearing. SIZING (wirescope SSE-tool_use, vendored+logs_main 37.5d): it's a CARRIAGE story not a $ story. $ is modest (~$0.94/day core, ~$2/day fleet, ~$60/mo) because tools[] is the first/cheapest cache-read segment (0.1×). The real figure = 578k (core) to 1.05M (fleet) tok/DAY of pure window occupancy that fires on a tiny fraction of turns. SKEW is the story: 77/177 core sessions load Monitor ≥1 turn; per-session min1/median1/mean147/max1765 — half carry it a single turn, a handful of all-day clodex-hand-style monster sessions carry it thousands and dominate (one 1765-turn session = ~3.4M tok alone). So value is CONCENTRATED in long persistent sessions = exactly clodex/clodex-hand all-day; near-zero for short sessions. Ranked by window-occupancy (token discipline) it LEADS the roster work; ranked by $ it's small. DESIGN: one shared watcher script; TWO source shapes — stream-watch (line-buffered tail -f / cmd stdout / ws: source, emit on matching lines) vs state-watch (diff-watcher UPGRADE: poll target, emit only on transitions, owns polling — wirescope's #4, better than Monitor's every-stdout-line + easier to arm right). Splitting per surface keeps each help text short+true, else agents arm BLIND watchers.
