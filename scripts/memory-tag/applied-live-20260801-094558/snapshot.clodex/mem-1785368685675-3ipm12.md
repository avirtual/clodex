Wirescope tail-hint channel (Clodex integration, settled 2026-07-29). Registration is CLODEX's job; wirescope owns a content-agnostic slot and authors no text. Three observations, NONE substitutable for another: (1) `capabilities.hints` on `/_identity` for existence — NOT `endpoints.hint`, which exists and points at `/_hint`, the unrelated per-agent spawner override, so a presence check on the wrong key passes while the surface is absent; (2) `capabilities.hints.system_tail_fallback` as a HARD precondition, because cli-hooks.js emits a trailing role:"system" message on every Clodex-managed session, making system_tail the ONLY delivery path — with the fallback off every request declines `marker_downstream` and the feature is a silent nothing; (3) `GET /_hints?agent=<glob>` for whether your scope resolves. `available` means REACHABLE, never "working" or "a hint is registered" — it is the only key on that handshake where truthy != operating (stats/ping/prune have no registry), so the wrong reading is correct inductive generalization from every sibling. A handshake is constitutively unable to answer a routing question: routing is a property of a request, and the handshake spends nothing. Channel design split: volatile STATE (peer warmth, parked dm, ticket counts) goes over tail hints, which live exactly one request; EVENTS (dms, assignments) stay on PTY injection, which is permanent and re-billed every turn forever. Agent route names arrive derived as `clodex-clodex-<hash>`, unknowable pre-first-request, hence globs (`clodex-*`).
