Teams design SETTLED (docs/teams-design.md, 07-19, jointly with designer + Bogdan's rulings). Load-bearing resolutions: (1) PROJECT IDENTITY = cwd + in-repo .clodex/team.json — the manifest IS the project; live team state in ~/.clodex keyed by project root; sessions join by cwd-under-root. Workspaces are TOPICAL/VISUAL groupings holding sessions from MULTIPLE projects — never the project boundary (workspace-promotion idea was proposed and RETRACTED; false premise only Bogdan could catch). (2) Convention over core for mechanisms AND identity; only core promotions: retire (v1, via clodex-team exec cmd) + project:role naming (costed v2; session-name regex has no ':' so v1 = project-role prefix). (3) Solo team is ~80% of usage = the product; ship order: solo-lead discipline + task ledger FIRST, multi-role second. (4) Cost spine: 6 waste lines W1-W6 (W6 wake amplification: turns are the expensive unit, tokens their payload), 3 currencies (tokens×tier / operator attention / tail risk), delegation threshold turns-denominated, REOPENED flag = honesty check on down-tiering. (5) Roles: manifest entries with instantiate: session|subagent (policy, promotable); seats earned by addressability/initiative/visibility/resumability, NOT memory; reviewer = cold subagent always, even solo. (6) Standing/maintenance teams = forward test: no v1 decision may assume dev-work or a present operator; 3am-authority declared in template posture, "wake the human" as explicit runbook entry.
