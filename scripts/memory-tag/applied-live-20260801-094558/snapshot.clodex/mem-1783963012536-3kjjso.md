Transcript-analysis lessons (07-13, transcript-stats arc): (1) A "re-read %" metric MUST separate pagination (different offset into a large file = new bytes, legitimate) from true redundancy (identical-args or full-read-after-prior-read). Fleet corpus: 64% naive re-read rate collapsed to 0.65% truly redundant once split — the 64% was measuring pre-refactor file SIZES, not wasteful behavior. Bogdan spotted it; my initial "re-read churn is the dominant cost" conclusion was RETRACTED and the wirescope read-after-own-edit stub idea lost its evidence. (2) Pattern across the week: this is the second retraction caused by an aggregate hiding composition (first: per-request $ normalization in the L2 A/B). Rule: before concluding from a rate, decompose it by the mechanism that could generate it innocently; also report per-session, not just per-agent — one locked-in session (378 bare cd's) dominated a fleet trend. (3) Corpus facts worth keeping: transcripts live in ~/.claude/projects/<munged-cwd>/, subagent sidechains in <dir>/<sessionId>/subagents/agent-*.jsonl (NOT inline), assistant records repeat usage per content block (dedupe by requestId or sums inflate 2-3x), compact marker = system/subtype:compact_boundary + user isCompactSummary.
