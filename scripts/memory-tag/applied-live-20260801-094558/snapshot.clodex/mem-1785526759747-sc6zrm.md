NEVER EMIT A DM IN THE SAME REPLY AS THE SPAWN THAT CREATES ITS TARGET. Hit twice within one hour on 2026-07-31 (hintprobe, then hintprobe2) despite an older pinned memory about spawn/dm non-atomicity — the older note was framed as a "gotcha" and did not survive contact with momentum. The rule in operational form: `[agent:spawn]` is asynchronous; the ONLY safe sequence is emit the spawn, END THE REPLY, wait for the `[agent:spawn] ok: spawned "<name>"` line to arrive in input, and dm only in a LATER reply. A dm to a not-yet-existent seat bounces with `no agent named "<name>"` and the message is lost, not queued. Corollary observed the same session: the bounce is silent about ordering — it reads exactly like a wrong NAME, which is how I misdiagnosed the first one as a naming error and looked up the roster instead of noticing the ordering.
