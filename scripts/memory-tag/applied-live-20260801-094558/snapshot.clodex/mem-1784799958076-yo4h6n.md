Product-design brainstorm captured in docs/plugin-vision.md (2026-07): clodex → core + public plugin API. Core = wb-wrap seed (wrapped agents, local dm/who, status bar, session lifecycle) — the complete "Eugen" viewer product; the tell for core-vs-plugin is "can a message leave the machine" (local dm=core, peering=plugin). Plugins = JS modules conforming to a PUBLISHED, versioned host API (extension-point taxonomy: status bar, sidebar, intent grammar [prompt line + handler], session menu, settings — the one-way-door decision). Load-bearing insight: a plugin's JS half owns its own coupling; core defines ONLY core↔plugin, never plugin↔backend (wirescope-js is the adapter to python-wirescope over wirescope's private wire; core never learns the word "wirescope"). Feasibility = LSP/VSCode shape, proven; two true impossibilities: clean live-unload of in-process JS (restart boundary) + in-process Python (always separate process). Trust boundary = process boundary (BYO plugins go out-of-process). T58's conditional grammar is the shipped first brick of plugin-contributed intents. Personas = modpacks (consent-scoped settings kills the million-checkboxes problem by removing overwhelm's CAUSE, not hiding it). Two ship-anytime principles: (1) auto-actions must self-attribute (why fired + how to disable, inline) — Eugen's surprise compact; (2) capture the passive-observer persona. Business case: funnel/larger-user-base — vanilla is the wide market, mods keep the deep end. NOT a plan; brainstorm only.

That's the durable pointer down. The vision's now in three places that survive a compact: the full note (`docs/plugin-vision.md`), a scoped memory unit pointing at it, and — until it compacts — here.

Where we landed, one line: **clodex = wb-wrap core + a published mod API + a plugin ecosystem, personas as modpacks — vanilla for the wide market, mods for the deep end, one engine, and the thing you defend is the seam, not the feature list.** Good brainstorm. It's safe now; pick it back up whenever.
