BUG (diagnosed, unfixed) — `[agent:file view PATH]` fails for sessions without a LOCAL workspace window (sandboxed/headless/web nodes) with "your workspace window is closed", even when an attached peer viewer OR the web session could receive it. Root cause: session-manager.js:3555-3566 `_handleFileIntent` — the `view` branch does `windowForSession()` → if null, replies error and RETURNS at line 3556, BEFORE the peer-mirror `getRemoteServer().pushUiEvent(name,'fileView',...)` at 3564. So delivery is wrongly gated on a local BrowserWindow; the peer/remote push (which works — worker@test confirmed `file view` works when triggered directly in the web session, same closed-window state) is never reached. Correct fix: decouple delivery from the local window — send to local window IF present, ALWAYS attempt the peer push, and error ONLY if neither a local window nor an attached peer viewer received it. Touches the peering subsystem (read docs/peering.md first; pushUiEvent semantics — need "did a viewer actually receive it" to decide when to still error). No test covers this branch; fakeWin/createSessionManager(deps) harness in test/session-manager.test.js is the seam. NOT the workbench-popover bug — that one (backdrop-click dismiss, workbench-popover.js:547) is the chosen live-demo build.
