GORGE-ONCE BRAIN PATTERN — settled mechanics (proven over 5 runs, 2026-07-25).
Harness: ~/clodex-brain/run.sh. Modes: poem (machinery test) | mega (corpus.v1) | mega2 (corpus.v2 + review findings). Args: MODE MODEL EFFORT.
Shape: curated corpus via --system-prompt-file (FULL REPLACE, not append) + --tools "Write" + --safe-mode + one absolute output path baked into the TASK.
HARD-WON GOTCHAS:
- --system-prompt-file strips the dynamic # Environment block, so the agent has NO cwd awareness. The output path MUST be absolute inside the task text.
- Write cannot overwrite a file it hasn't read -> rm -f the target before every run.
- CLAUDE_STREAM_IDLE_TIMEOUT_MS is the var that matters (NOT API_TIMEOUT_MS). Default kills long syntheses at ~303s. Three opus-5 runs died at 304.5/304.0/303.0s costing $0.79 each before this was found. The client's idle clock counts CONTENT deltas; SSE pings do NOT reset it, so a model slow to first content trips a watchdog the proxy cannot see.
- Cache TTL: for gorge-once (exactly ONE re-read, the tool_result round-trip) 5m-held is cheapest, then no-cache, then 1h. 1h needs >=2 re-reads to pay for itself and gorge-once ships one by construction. BUT at max effort P(5m blown) ~= 1 and a blowout costs a full second corpus write, so drop FORCE_PROMPT_CACHING_5M (default is 1h) for long runs.
- cache_write ALREADY pays for the model's first pass over the corpus. There is no separate read on that request. N=1, not 2.
- The output path rides INSIDE the prompt, so model-tagged filenames perturb the cached prefix. Token mismatch => hash tools + system + messages (all three) before blaming the tokenizer.
