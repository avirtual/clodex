Error-message pattern (ruled 07-17, batch 7): one pattern app-wide for toasts AND alerts — "X failed: reason" (operation-first, e.g. "Save token failed:", "Create sandbox failed:"). Never "Failed to X", "Could not X", or bare "Failed:". Exempt: validation verdicts like "Mount rejected:" (not operation failures). Also ruled: thrown-exception vs returned-error paths must use the SAME user-facing wording ("failed:", never a "error:"/"failed:" split); toasts print friendly labels, never raw internal ids.
