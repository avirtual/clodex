Clodex "tools via exec intent" pattern (built 2026-07, docs/exec-tools.md): the exec intent is a one-shot fire-and-forget CONTROL plane (argv from registry, payload on stdin, stdout dropped, launcher SIGKILLed at timeoutMs, feedback via replyStderr). For tools with ongoing output, run a DETACHED worker that streams results back to the invoking agent as DMs over run/<agent>/agent.sock ({from,body,type:'dm'} — the "message from outside clodex to an agent inside" path, envelope handled by _onIncoming→_deliverMessage). First tool: clodex-monitor (scripts/clodex-monitor.js + ~/.clodex/library/exec/clodex-monitor.json), replaces the built-in Monitor tool. Actions start/stop/list; agent self-supplies its name in payload (v1). Grant a seat via intents:["exec"] + execCommands:["clodex-monitor"]. Known v2: pass invoker name to exec child via env (the one core session-manager.js change) to drop the self-name field.
