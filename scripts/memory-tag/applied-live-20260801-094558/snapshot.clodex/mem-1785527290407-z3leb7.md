MEMORY CONSOLIDATION — THREE OBSOLESCENCE CLASSES, AND TAG BUCKETS CATCH ONLY SOME. Measured 2026-07-31 while validating the t129 consolidation pass against ground truth.

(1) CONTRADICTED — a newer unit asserts the opposite of an older one. (2) EXPIRED — never wrong, just scoped to a moment that passed (Bogdan's framing: agents save session decisions that are must-know for one or two sessions after a compact, then become history; the store had July-27 ticket bookkeeping still PINNED days later). (3) PARTIALLY ROTTED — discovered by counterexample: mem-1783524813485-l7u6nx is an omnibus boot pin holding a dozen unrelated standing rules, of which exactly ONE clause (the contrarian being retired) is false. `keep` serves a false clause with pin authority forever; archiving destroys a dozen live rules. Neither verdict fits because THE UNIT IS THE WRONG SIZE. A forced verdict here is worse than an honest "does not fit" — hence a fourth verdict that archives nothing and surfaces for review.

THE STRUCTURAL LIMIT: tag-bucket consolidation compares units that share a tag, so it can only see contradictions between units whose OVERALL TOPICS coincide. The l7u6nx/5c0ues contrarian contradiction is invisible to it — disjoint tags (memory-and-docs,product-philosophy vs team-delegation,cold-review), never in one bucket, never read side by side. Verified on the live store, not hypothesized. The tagger is NOT at fault: each unit is tagged correctly for what it is about. The contradiction lives at CLAUSE granularity inside a multi-topic unit while tags live at UNIT granularity. Any future retrieval or curation design that keys on whole-unit topic inherits this same blind spot.

THE CHEAP FIX (t134): units frequently DECLARE their own supersession in prose — 5c0ues literally says "supersedes the 07-10 'contrarian retired, never consult' rule in the boot pin". A past session already did the judgment and had no structural way to record it. Grep for that language, resolve targets where possible, feed the pairs as an extra bucket. Not exhaustive, but it catches the cases where the work is already done.

GENERAL LESSON, third time this week: I nearly ran a pass that would have reported success while structurally unable to see the one defect I could verify by hand. Validating a new instrument against a case whose answer you ALREADY KNOW is the only thing that catches this class — a green run on unknown data cannot.
