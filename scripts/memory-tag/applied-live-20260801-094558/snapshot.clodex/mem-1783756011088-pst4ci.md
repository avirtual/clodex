Intent gating (task #5, shipped 07-13, commits a9275c5..1cf4027): per-session `intents` allowlist. Semantics: ABSENT (non-array) = living all-enabled default (future intents light up); `[]` = real everything-gated; `name` never gateable; exec/resend gateable but NO prompt line. Send-side only — dm-gated seats still receive. intents is a create() PARAM (17th positional) persisted by create()'s own upsert — NOT a post-create seed — because the prompt bakes inside create() and kill()+recreate rebuilds persistence from spawn args only (same hole stripLevel re-asserts for). buildIpcPrompt(intentsList) in ipc-prompt.js assembles per-seat prompts; GRAMMAR_LINES owns prompt-physical order INDEPENDENT of intent-catalog's checklist/serialization order (two orderings, two owners); double byte-pin buildIpcPrompt(null)===IPC_PROMPT===buildIpcPrompt(all) makes drift a failing test.
