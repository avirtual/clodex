BOGDAN'S RULING ON MCP (2026-07-27) — settles t44's open question, and his route is better than my option:

DIRECTION: "we do a good job at not touching user project files, whether they are code or .claude/ files and we should keep that. but clodex surfaces by design where the waste is happening and generally speaking mcps are a context hog, so maybe we should surface them when they are there. then we will decide if we handle the part that maybe skips them from the roster (if we cant do it from clodex settings, it could be done, maybe, with the help of wirescope)"

THREE THINGS SETTLED:
1. NEVER-WRITE-A-USER-FILE IS NOW AN AFFIRMED STANDING RULE, not merely an observed invariant. Covers code AND .claude/ files. Clodex's whole strategy stays session-scoped injection into disposable ~/.clodex artifacts.
2. SHIP TIER (b) — surface MCP servers WHEN PRESENT. A user with no MCP servers sees NO new UI (not an empty section). Rationale in his words: Clodex surfaces by design where the waste is, and MCPs are a context hog.
3. STRIPPING GOES THROUGH WIRESCOPE, NOT CLODEX SETTINGS — and this DISSOLVES both objections to tier (c). The wire ALREADY strips claude_design per-server and keeps real MCPs (the surgical path session-manager.js prefers). Generalizing from one hardcoded server to a user-chosen set writes NO CONFIG FILE AT ALL: no user-tree write, no renderer-authored command line, no unverified scope-merge, no copy-through. BOTH t44 objections to (c) were objections to doing it via .mcp.json. Through the wire they evaporate. NOT YET DISPATCHED — surfacing comes first, because you cannot choose what to strip until you can see what it costs.

BLOCKING GATE ON ALL OF IT: MCP tools being prefix-keyed mcp__<server>__* in the LIVE roster is derived from transforms.py:1185's contract and NOT OBSERVED ON REAL BYTES (zero MCP servers on this box). It is the key for BOTH grouping and per-server stripping. t46 step 0 confirms it on real bytes or the ticket stops.
