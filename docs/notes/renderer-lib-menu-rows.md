# renderer/lib/menu-rows.js

## readMenuRows
Measured by scripts/explore/capture-menu.js on a bare node-pty at 100x40 fed into `@xterm/headless` (2026-09-26): Claude Code 2.1.283, Codex 0.157.0 (`-c check_for_update_on_startup=false`), Muse Code 1.4.0, each in a fresh trusted scratch repo. `/`, `c`, `l`, `o` were written separately, 50 ms apart; each state is a fixture in test/fixtures/menu-states/. Codex and Muse have no command matching `/clo` (their three-chars fixture reads null), so their arrow/backspace/escape/tab/paste states were taken on `/co`.

Where the menu is: Claude — below the composer's closing rule, one entry per name with the description wrapped onto continuation rows indented to the description column, ended by a blank row; normal buffer. Codex — above the composer `› /…`, one blank row between; alternate buffer. Muse — between the composer and the closing rule, at most 7 entries plus a `↓ N more` row; a query with no command paints `↵ Send as prompt    No slash command named /…` instead.

Selection marker: Claude — colour only, the whole entry (continuation rows too) in fg `#5769f7` against `#666666` (default dark theme; `CLAUDE_SELECTED_FG`); no row is selected when the query matches only descriptions (`/clo`), `/`, `/c`, `/cl` preselect the first. Codex — glyph `›` in column 0 plus the whole row in SGR 7 (inverse) and bold. Muse — colour and weight on the name only, bold fg `#5aa0ff` against `#ccd3db`.

Matched characters: Claude bolds them in names AND descriptions (`/clo` bolds `clo` in `cloud`); it also matches clipped description text, so `/built-in-browser` and `/computer-use` are listed with no visible bold. Codex bolds them in names only and only on unselected rows (the selected row is bold throughout); it matches names only. Muse bolds nothing and matches names and `(/alias)` only. `matchSpans` offsets are into `name` or into `description` with continuation rows joined by one space.

Description column: the first run of two or more spaces after the name. Claude — one column for the session whatever the filter (32 here, 26 in a repo with other skills). Codex — 2 + widest filtered name + 2. Muse — 2 + widest filtered label + 2, where the widest label can be a row scrolled out of view.

Keys: Down/Up move the selection by entry (a wrapped Claude entry moves as one) and never scroll the screen (baseY 0 and the anchor row unchanged through every step). Codex wraps from the last entry to the first. Tab completes the selected entry, or the first when none is marked: Claude and Codex close the menu (`/schedule`, `/compact`), Muse keeps it open on the one completed row. Escape closes the menu and keeps the typed text on all three; Muse swaps in its no-match hint. Backspace re-filters on all three; Muse keeps the previously selected name selected, Claude and Codex reset to the first. Codex sends the draft as a message on Tab when no menu is open, so a transport must not forward Tab blindly.

Timing, keystroke write to the last buffer change (10 ms poll, 100 ms silence), single keys: Claude min 12 / median 13.5 / max 74 ms (n=14, the max is Escape erasing the menu); Codex 12 / 19.5 / 26 ms (n=18); Muse 12 / 13.5 / 26 ms (n=18). First byte back: Claude median 10.5 ms, Codex 3, Muse 1. Four keys 50 ms apart settle 216–218 ms after the first write on all three.

Echo bytes (typing `c` after `/`): Claude writes the character with relative moves in the same chunk as the menu repaint — `\x1b[?25l\x1b[3D\x1b[22B\r\x1b[3C\x1b[22Ac\r\x1b[3C\x1b[2B…`, the menu following from `\r\x1b[2C\x1b[2B`. Codex wraps each frame in `\x1b[?2026h … \x1b[?2026l` and echoes with an absolute move onto the composer row (`\x1b[37;6Ho`), menu rows by `\x1b[<row>;1H`. Muse first parks the cursor (`\x1b[39m\x1b[49m\x1b[59m\x1b[0m\x1b[8;4H`, ~1 ms), then ~12 ms later `\x1b[8;4H\x1b[38;2;204;211;219;49mc` and the menu rows by absolute moves. None separates echo from repaint at the byte level, so the transport tells them apart by row on the settled buffer: the anchor row is the echo, everything `readMenuRows` collects is the menu.

Bracketed paste `\x1b[200~/clo\x1b[201~` (Claude) and `\x1b[200~/co\x1b[201~` (Codex, Muse) opens the same menu as the typed keys, in one repaint.

Verdict: yes — forwarding each keystroke to the pty and reading the settled buffer with `readMenuRows` reproduces the CLI's own menu in our pane for all three: every key settles within 26 ms except Claude's Escape (74 ms), selection and the description column are recoverable from text plus cell attributes, and arrows never scroll the screen, so the anchor is stable. Only Claude Code delivers what the operator asked for — fuzzy matching over descriptions and per-character bold spans — and it is the one whose selection marker is a theme colour, so a theme other than the default dark one needs its colour measured. Codex and Muse transport just as well but their menus match names only; Muse shows no match highlight and Codex none on the selected row. A whole draft can be forwarded at once as a bracketed paste.
