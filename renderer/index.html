New session defaults

Tools and MCP for sessions you create from now on

Both apply at spawn and only to new sessions; existing ones are unaffected.

Default tools

Unchecked tools are denied for new Claude sessions by default (you can still adjust per session at create). A consistent set lets sessions share one cached tools segment — leaving rarely-used tools off also trims each prompt.

Claude MCP

Claude Code auto-injects the built-in claude_design connector (~20 tools, ~4k tokens every turn) with no global opt-out. A routed session is usually handled by the proxy, which removes just those tools and keeps your real MCPs. But it falls back if the proxy is too old to strip or is unreachable at spawn — so routed is not a guarantee. The fallback uses --strict-mcp-config, which is all-or-nothing: it disables every MCP server, including project/user ones. The IPC log says whenever it is used, and why. Leave it off unless your unrouted agents use no MCP.

Environment variables

Extra variables for every session this app spawns

Extra environment variables merged into every wrapper session's process (claude, codex, and bash), on top of the machine environment. Precedence is machine < Global < This workspace < per-session (set in the New Session dialog). Mark a value Secret to store it write-only — it's kept on disk with 0600 permissions and never shown again after you save (the row shows only that a value is set). CLODEX_REMOTE_TOKEN is reserved and can't be set here. Applied at spawn — restart a session to pick up changes.

Scope

Traffic optimization

Wirescope, and the transcript bake and memory hints that run on it
Wirescope

Wirescope is the local proxy every optimization below runs on: it routes each agent session's API traffic through a process on this machine, started and managed by Clodex (first run sets up a private Python environment; needs a system python3), and from there does the cache-warming, cost telemetry and wire trimming. Applied at spawn — running sessions pick it up on restart; sessions work normally without it, they simply are not optimized. Turning this off turns off everything below it.

—
Resume-time transcript bake

When Clodex starts, hand each resumed session's on-disk transcript to wirescope, which bakes it down to what it already strips on the wire, so the replayed prefix is permanently slimmer. The original is backed up next to it first, and any error resumes it untouched. Mostly free: what it removes, the wire was dropping anyway. The exception is a turn made up entirely of thinking — the wire has to keep those, so baking one out re-caches that turn once, and it stays slimmer from then on.

Contextual memory hints

On a pause in your typing, match the draft against the agent's own memories and the common store, and attach the best matches to that turn as an ephemeral hint the agent may ignore. Units already in its context are skipped, and the same unit is not re-offered for ten minutes. Wirescope is what attaches the hint, so nothing is matched or sent when it is off.

Word matching picks the right memory about 40% of the time; a local embedding model raises that to about 64% by matching on meaning rather than wording. It reorders candidates, and it is also the only thing that can answer a short question about you ("where do i live") — word matching scores every record identically on a one-word query, so it has no way to pick. Whether to hint at all is still decided by word matching everywhere else, which is the half that knows when to stay quiet. Needs Ollama running locally with the nomic-embed-text model; when it is unavailable this silently falls back to word matching, and short personal questions simply stay quiet.

Send the panel selection

Two ways to hand the agent something from a bottom-panel tab, so you can point at a log line or a command's output without pasting it. Selecting alone is ephemeral: it rides the next request only, says it may be irrelevant, and is gone whether or not it was used — use it or lose it. Copy is a hard copy: it goes into the conversation itself on your next message and stays there, and still copies to your clipboard. Nothing is sent while the panel is collapsed, and any token from your clodexctl contexts is redacted out of a selection first — that redaction is specific to this feature and does not apply to the terminal reports below. Selecting needs wirescope running; Copy works either way. This is a separate decision from memory hints — it forwards whatever you highlighted, not what the agent wrote.

Tell the agent what you run in the terminal

Two separate things, so you can pick them apart: whether the agent can run a command in your Terminal tab at all, and whether it is told about the commands you run there. A report is the command line and its exit code, plus the tail of the output when it failed; a command that succeeded sends its line alone. Reports ride along with your next message rather than interrupting the agent, and nothing is sent for the shared terminal when no session is selected. This adds a small generated startup file to the terminal's shell so it can mark where each command begins and ends; your own .zshrc or .bashrc is sourced normally and is never modified. Needs zsh or bash 4.4+ — another shell simply gets an ordinary terminal.

Reports are sent verbatim and unredacted — a command line with a token, a password in a URL or an Authorization header goes as written. Switching away from "everything I run" also discards any of your commands still waiting to be sent; ones already merged into a conversation cannot be recalled. Switching that off takes effect immediately, but turning marks on or off (the "Off" choice) applies to terminals opened afterwards.

Capture logs

The proxy keeps per-session request captures on disk to power cost and cache-bust forensics. They accrue over time; clearing collapses old sessions to their billing receipts (cost history is preserved — only the detailed request forensics are removed) and clears the probe-traffic bucket. Active, warm, and recent sessions are never touched.

Phone access

Read and reply to sessions from a browser

Serves a chat-style web view of your agent sessions (transcript + send box, no terminal) on this machine only (127.0.0.1). To reach it from your phone, put both devices on a tailnet and run tailscale serve <port>, or use an SSH tunnel — Clodex never opens a network-visible port itself.

—

Optional access token that gates the wire. Paste a token you keep a copy of — you'll need it for ?token= bookmarks on your phone. Stored write-only on this machine; it's never shown again after you save. The CLODEX_REMOTE_TOKEN env var, if set, overrides this.

Terminal sharing

Lets a peer that can reach your tunnel open a terminal on this box. Not a shell of its own — it attaches to the same drawer shell your own Terminal tab shows, is handed its scrollback, and can type into it while you are. The peer wire has no per-caller identity, so this is one switch for every peer, not a per-peer permission. Turning it off closes any remote shell that is already open.

Session discovery

Adopt Claude/Codex sessions started outside Clodex

Clodex can find Claude/Codex conversations on this machine that it isn't managing — including ones you started in a plain terminal — and let you adopt them (File ▸ Discover Sessions…). When enabled below, it checks on startup and offers any it finds; adopting resumes the conversation in a Clodex-managed session (it never attaches to a running process or spawns anything automatically).

Plugins

Plugins extend Clodex in-process. Turning one off removes its buttons, panels and styles from every open window immediately. A plugin whose activate() throws is skipped and the app boots regardless; after two consecutive failed launches it is held back until you retry — your on/off choice is never overwritten. A plugin that has its own settings shows a Settings button on its row. Set CLODEX_PLUGINS=0 to skip the plugin system entirely.

Peered Clodexes

Attach to agent sessions running in a Clodex on another machine: view their terminals live and, after an explicit "Take control", type into them. Give each peer an SSH host (laptop2 or user@laptop2) and Clodex maintains the tunnel itself — needs key-based SSH (no password prompts) and Phone access enabled on the peer. Test & Set Up checks the host over SSH and, if no Clodex is running there yet, offers to install one. The URL field is the manual alternative for tailnets or custom tunnels. Anyone who can reach the peer's endpoint can drive its sessions — treat it like shell access.

Sandboxes

Run Clodex engines inside local Docker containers and use them as peers: agents placed in a sandbox have their shell, file writes, and network confined to the container, while keeping full Clodex features over the peer wire. Each container publishes to 127.0.0.1 only.
