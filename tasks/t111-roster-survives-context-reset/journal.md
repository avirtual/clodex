# t111 — the roster does not survive a context reset

## The complaint

The operator, on seeing the lead spawn a cold subagent while a warm teammate seat
was live in the same cwd:

> "clearly you spawning a subagent to implement this, rather than using the
> clodex-hand team mate signifies something gap"

and then:

> "the team composition was supposed to arrive in your context, it used to do
> that. the mechanism exists, it might be incomplete or it might not survive
> compacts"

Correct on every point. It used to work, the mechanism exists, and it does not
survive a context reset.

## Diagnosis (verified, not inferred)

**A key mismatch.** Two stamps in the same store model the same kind of thing and
disagree:

```
stores.js:396   setRosterSent(name)            -> entry.rosterSentAt = Date.now()
stores.js:519   markDigested(name, sessionId)  -> entry.digested.push(sessionId)   // 50-entry ring
```

`rosterSentAt` is **per-seat and permanent**. The gate that reads it is
`session-manager.js:1309`:

```js
if (existingEntry && existingEntry.rosterSentAt) return;   // _maybeInjectComposition
```

So the roster is delivered **once in a seat's entire lifetime**, and never again
across any number of `/clear`s, compacts, restores or restarts.

**The codebase already states the correct intent.** `test/createdat-restart.test.js:135`:

> "rosterSentAt is the contrast: it IS conversation state, so a fresh restart ...
> a new conversation has no roster in it"

That is exactly right, and the implementation contradicts it. Commit `3fe1bb5`
("no roster re-inject on resume") got the RULE right and the KEY wrong.

**Live proof, the lead's own record** (`sessions.json`):

| field | value |
|---|---|
| `rosterSentAt` | 1784673498728 = 2026-07-21T22:38Z |
| `createdAt` (current session) | 1784934234935 = 2026-07-24T23:03Z |
| gap | **72.4 hours**, many resets ago |

The seat has had no roster in context for three days and there was no signal of
any kind. Compare `hook-digest.json` for the same seat: 8275 bytes of memory
digest, correct and current, because it is **re-baked before every spawn**.

**The structural difference, which is the actual bug.** The roster is delivered
as a *message* (`_injectRoster` -> `_deliverPassive`, `session-manager.js:1352`)
that parks and drains into conversation history. A compact discards conversation
history. The memory digest survives because it is regenerated into
`hook-digest.json` pre-spawn rather than remembered. **Anything that must survive
a context reset has to be regenerated, not delivered.**

## Three holes, and why sessionId alone does not close them

| Path | sessionId | Today | Wanted |
|---|---|---|---|
| `/clear` | NEW id | suppressed by stale stamp | re-deliver |
| restore / restart | NEW id | suppressed | re-deliver |
| `/compact` | **SAME id** | suppressed, history gone | re-deliver |

Keying the stamp on `sessionId` (mirroring `markDigested`) fixes the first two
and **misses compact**, which preserves the id. Compact is the case the operator
actually hit.

**The trigger for compact already exists.** The generated `hook.sh` receives
`source` from the CLI and branches on it — verified in the live script for seat
`clodex`:

```bash
if [ "$SRC" = "startup" ] || [ "$SRC" = "clear" ]; then
  cat ".../hook-digest.json"
else
  cat ".../hook-output.json"      # <-- compact lands here: name only, no digest
fi
```

So `SessionStart` **does** fire on compact and the branch is one condition away
from serving the digest. This is a policy choice in the generated bytes, not a
missing mechanism.

## The fix

**Two parts. Both required — either alone leaves a hole.**

### Part 1 — put the roster in the boot digest

`writeClaudeDigestFile(name)` (`cli-hooks.js:18`) composes
`"You are the clodex agent named '<name>'."` + memory digest. Add the team roster
as a third block when the seat's cwd resolves to a team.

`formatRoster(team, liveSeats)` (`team-manifest.js:375`) is the existing
renderer — reuse it, do not write a second one.

> **Do NOT put the roster in `formatTeamBlock`.** `team-manifest.js:362` says
> plainly why: that text is part of the **cache-stable system prompt**, and
> composition changes over a seat's life. The digest file is `SessionStart`
> `additionalContext` — conversation content, NOT the system prompt — so it does
> not bust the prompt cache. Preserve that comment and its reasoning; a later
> reader must not "consolidate" the two.

`writeClaudeDigestFile` currently takes only `name` and lives in an
Electron-free module whose deps arrive through `createCliHooks({...})`. It has no
way to resolve a team today. Inject a seam (a `resolveTeamFor`-style function)
through the factory rather than importing session state into it — the module's
electron-free, dependency-injected shape is load-bearing and
`test/free-identifier-leaks.test.js` gates it.

**Re-bake on composition change.** `writeClaudeDigestFile` is already re-called
on memory mutation (`session-manager.js:2539`). `_notifyComposition`
(`session-manager.js:1391`) is the equivalent moment for the team, so the digest
must be re-baked there too — otherwise a seat that spawns after this one boots
is absent from the digest until the next reset.

### Part 2 — serve the digest on compact

Change the generated `hook.sh` branch to include `compact`.

**The generated bytes are test-pinned** (CLAUDE.md: "Generated bytes are
test-pinned"; template-literal interiors are byte-sensitive). Expect to update
the pinning test, and update it to assert the NEW correct bytes — do not weaken
it to stop caring about the branch.

Note what else lives in that same `if`: the `clear`/`compact` promptcache
baseline reset already treats the two identically. Serving the digest on compact
makes the two branches agree about what a context reset means.

### Part 3 — fix the stamp

With Parts 1+2 the digest carries the roster on every reset, so `rosterSentAt`'s
job shrinks to what its name says: "has this seat ever been told, in *this*
conversation". Key it on `sessionId` like `markDigested`, or delete it if Part 1
makes the message path redundant for claude seats.

**Decide deliberately and journal the decision**, because the message path is
still the only one that works for **codex** seats (no `hook-digest.json`; the
codex path stashes a team ref and flushes via `_settleBoot`,
`session-manager.js:1377`). Do not regress codex while fixing claude.

## Scope boundary

Core only: `cli-hooks.js`, `stores.js`, `session-manager.js`, `team-manifest.js`
and their tests. **No wire/ changes, no wirescope involvement** — the roster does
not ride the wire and this crosses no other agent's repo.

## Verification — read this, the failure mode here is silence

This bug survived three days undetected because a missing roster looks exactly
like a team with no other seats. The lead's own prompt even says "most days the
team is just you — that is the correct configuration, not a fallback", which
makes the absence self-confirming. **So a test that only asserts "the digest
contains a roster when a team exists" is a false-green risk**: ask what it would
look like if the delivery had NOT happened.

Required:

- A test that a **compact-sourced** `SessionStart` yields the digest, not the
  bare name file. This is the regression that reproduces the operator's report.
- A test that a seat whose `rosterSentAt` is 3 days old and whose conversation
  has reset **still gets the roster**. Build it from the real failing shape.
- Byte-pin tests for the generated hook updated, not relaxed.
- The codex path still delivers via `_settleBoot`.
- **Mutation-check your own new tests**: break the fix deliberately (revert the
  `compact` branch) and confirm the new test FAILS. A verifier that only ever
  prints PASS is indistinguishable from one with a broken assertion.
